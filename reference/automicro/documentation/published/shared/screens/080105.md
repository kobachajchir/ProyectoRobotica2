## Variantes y estado

- 0x080104 distingue aviso de ingreso y formulario de permiso mediante source.
- Input/waiting/denied/timeout/blocked y resultado de sesión son fases diferentes.

## Campos y disponibilidad

| Campo | Tipo / unidad | Disponibilidad |
| --- | --- | --- |
| `screenCode/source` | u32/u8 → number / identidad/fase | reported; el source participa del discriminante |
| `pinDigits/pinIndex` | dígitos/índice local / edición PIN | unavailable-remotely; no se publican en el reporte de identidad; no usar ceros como observación |
| `estado de autenticación/TTL` | status/TTL / ms/boolean | separately-queryable; autoridad de sesión no es cursor local de edición |

## Acciones y transiciones

- Validación JSON usa screenCode/ámbito y espera resultado F4; los datos sensibles no se copian a documentación.
- Los eventos de encoder/USER pasan antes por la prioridad Permission del router.
- Concesión ejecuta continuación registrada; cancelación/timeout/bloqueo siguen políticas propias.
- Formulario PIN Web es entrada local y no una captura del framebuffer F4.

## Datos que impiden una copia exacta

- La réplica del formulario físico no puede inferir dígitos/posición desde 0x52/0x95.
- No confundir ACK de input consumido con permiso concedido.

- Una futura exposición de datos/píxeles debe definir permiso y enmascarado según el comportamiento deseado, mediante contrato explícito.
