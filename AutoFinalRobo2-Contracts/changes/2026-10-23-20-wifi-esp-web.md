# AFR2-20261023-20 — Wi-Fi independiente del Mega

23/10/2026. Pedido directo de completar pendientes propios ESP/Web sin tocar el enlace Mega trabajado en paralelo. Se revisaron el maestro, PLAN_ESP y los consumidores/servicios actuales. Alcance elegido: cerrar el flujo Wi-Fi ya previsto, que confundía aceptación del scan con resultado final y no ofrecía persistencia temporal en la Web.

## Cambios

- Web conserva estado global de scan idle/scanning/completed/failed hasta recibir `wifi.scan.result`; accepted solo inicia. Distingue resultado vacío, error de inicio, error del radio, resultados truncados a 16 y timeout local de 30 s. Evita inicios locales duplicados, limpia temporizadores/resultados al perder sesión y descarta errores de generaciones anteriores. Los eventos de radio siguen compartidos entre sesiones; no se agregan IDs ni correlación UART.
- Consulta `wifi.status` cada 3 s con WS listo y página visible, sin dependencia del Mega ni toasts periódicos. El lector automático evita solaparse consigo mismo; actualización manual sigue disponible. No se cambia el lector robot.state ni sus callbacks.
- Formulario ofrece el `persist` ya implementado en ESP: guardar para el próximo encendido o aplicar solo RAM. Temporal no elimina preferencias anteriores. SSID exacto sin trim, 1..32 bytes UTF-8; frase vacía o 8..63 bytes; se rechaza NUL. Contraseña se limpia después del envío y no se persiste en navegador.
- Configure accepted no equivale a conexión lograda. Se muestra el estado real STA, fallo de contraseña/red y fallback. Se aclara que, si cambia IP, puede requerirse abrir otra dirección; no se promete que el endpoint anterior encuentre la nueva IP.
- ESP comprueba retornos de mode/softAP/begin, informa fallos inmediatos y solicita AP de recuperación ante fallo de modo/AP. Sin contraseñas en status. Configuración guardada y aplicación/conexión siguen siendo resultados separados.

## Contrato local ESP↔Web

Mismos comandos y sobre afr2-ws-1. `wifi.status` agrega campos opcionales:

| Campo | Tipo y significado |
| --- | --- |
| applying | bool: configuración aceptada pendiente de aplicación |
| staStatus | disabled / connecting / connected / network-not-found / connection-failed / wrong-password; observación SDK |
| fallbackActive | bool: AP de aprovisionamiento/recuperación iniciado por servicio y activo; no implica STA conectada |
| scanRunning | bool: SDK aún ejecuta scan, incluso tras timeout del resultado |
| configPersisted | null si desconocido; true si última config se cargó/guardó en LittleFS; false si último cambio aceptado es RAM. No acredita conexión |
| configError | null o MODE_FAILED / AP_START_FAILED / STA_START_FAILED; error inmediato de aplicación |

Evento scan existente: status completed/failed, networks y truncated. No resuelve promesas requestId: actualiza estado del servicio. `scanRunning` permite impedir otra configuración/inicio mientras SDK siga ocupado. No cambia framing ni validación Mega.
